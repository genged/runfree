# Runfree 0.5.0

Initial beta release. Runfree starts Claude Code, Codex, or Pi inside a per-project
Docker workspace, routes their outbound HTTPS/WSS through a policy-enforcing proxy,
and keeps proxy-managed service credentials out of the agent container. Install with
`brew install genged/tap/runfree`, or without Homebrew with
`curl -fsSL https://raw.githubusercontent.com/genged/runfree/main/scripts/install.sh | bash`,
then run `runfree init` and `runfree` in a project directory.

- Supported: Apple Silicon macOS with Docker Desktop and Docker Compose, on the
  latest release only, best effort, with no response-time commitment.
- One published archive, `runfree-0.5.0-darwin-arm64.tar.gz`, ad-hoc signed and not
  notarized, with a SHA-256 manifest. Use Homebrew or the install script: a browser
  download is quarantined and Gatekeeper refuses it.
- Intel macOS and Linux are not published. They can be built from source, and a
  source build is not a support claim.
- The project workspace is writable by the agent, including its Git metadata, and
  project image builds run before the sandbox exists.
- Native Claude and Codex logins live in per-project agent state, not behind the
  proxy's credential boundary. Only proxy-managed service tokens get that protection.
- An allowed host is an allowed host: policy constrains where a request may go and
  what shape it may take, not what an agent chooses to send there.
- Docker itself, and the host, are trusted.
  [`docs/security.md`](../security.md) carries the full threat model, and
  [`docs/whats-new-0.5.0.md`](../whats-new-0.5.0.md) the tested versions and the
  limits of what was proved.
- Bugs and feature requests: GitHub Issues. Suspected vulnerabilities: private
  reporting as described in [`SECURITY.md`](../../SECURITY.md), never a public issue.
