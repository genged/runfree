# Runfree 0.5.1

0.5.1 is a hardening and maintenance release. It closes a gap where a startup
helper container could take a session's network address, makes Docker calls
that time out fail closed, bounds and cleans up the short-lived helper
containers that startup runs, and trims Docker calls from `up`, token sync, and
`destroy`. It also drops migration of pre-release configs: a
`.runfree/runfree.json` older than version 4 is now refused.

- Upgrade warning: a config below version 4, or one that still uses the removed
  `agent`, `paths`, or `project.*` keys, is refused before Runfree writes
  anything. Move `.runfree` aside, run `runfree init`, and re-add hosts and
  services. Configs created by 0.5.0 are already version 4 and need no change.
- The direct-egress deny-probe helper now gets a pinned address from a reserved
  block (`.13`–`.19`) outside the session pool. Before this fix Docker could
  give it a session address, and the proxy would serve it as that session.
- Startup helpers are killed at a fixed bound (30 s for deny probes, 120 s
  otherwise). A helper left behind by a crashed CLI is swept by label under the
  project lifecycle lock before the next start admits any session.
- A Docker call that times out, is killed, or fails to spawn never reads as
  success or as "not found".
- Fewer Docker calls on a warm `up`, during token sync, and in `destroy`.
- The first start after upgrading rebuilds the agent image, because its inputs
  changed.

Details, examples, and upgrade steps: [`docs/whats-new-0.5.1.md`](../whats-new-0.5.1.md).
